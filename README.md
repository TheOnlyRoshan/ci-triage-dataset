# CI Triage Dataset

A labeled dataset of continuous-integration (CI) failure logs, used to train and
evaluate an AI-powered CI failure triage pipeline.

Each entry pairs a real CI failure log with a known ground-truth label describing
*why* the build failed. Because every failure in this dataset was deliberately
injected into a controlled project ([expense-tracker-api](https://github.com/TheOnlyRoshan/expense-tracker-api)),
the correct label is known with certainty — making this a clean, reliably-labeled
training set rather than one relying on human guesswork.

## Failure categories

| Label                | Meaning                                                                 |
|----------------------|-------------------------------------------------------------------------|
| `genuine_regression` | A real code change broke a test — an actual bug needing a fix.          |
| `transient`          | An environmental blip (network timeout, upstream service error) unrelated to the code. |
| `flaky_test`         | A non-deterministic test failure (shared state, timing) independent of any code change. |
| `infra`              | The CI environment itself is broken (bad config, wrong runtime, missing dependency) — not an app bug. |

## Structure

```
dataset/
  genuine_regression/
  transient/
  flaky_test/
  infra/
```

Each folder holds one JSON file per captured failure.

## Entry format

```json
{
  "id": "genuine_regression_001",
  "label": "genuine_regression",
  "log": "...full CI failure output (stack trace, failed assertions)...",
  "injected_fault": "human-readable note on what was changed to cause this failure",
  "commit_sha": "abc123",
  "timestamp": "2026-07-25T18:00:00Z"
}
```

Field notes:
- **`log`** and **`label`** are the actual training pair (input and ground truth).
- **`injected_fault`** is documentation for reference only — it is *not* fed to the model.
- **`commit_sha`** records the commit the failure occurred on, so a downstream
  triage agent can later inspect the actual code change to reason about root cause.

## Purpose

This dataset supports a CI triage pipeline that classifies build failures and,
for genuine regressions, can trace the failure back to the commit that caused it.
The dataset is generated by deliberately injecting each category of failure into
the controlled test project, capturing the resulting CI log, and labeling it.
